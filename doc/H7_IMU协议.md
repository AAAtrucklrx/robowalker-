## 4. 最大的坑：不要用 `cat` 读串口

```bash
# ❌ 错误：帧长看起来在 76~100 字节之间抖动，像是"变长协议"
cat /dev/ttyACM0 | xxd

# ✅ 正确：pyserial 默认 raw；或先显式设置
stty -F /dev/ttyACM0 raw
```

原因：`cat` 读取会经过 tty **行规程（line discipline）**，它会对二进制流做
字符翻译、吞掉某些控制字节，于是看上去帧长忽长忽短、自相关完全对不上。
**这个假象曾让我以为协议是变长的。** 换成 pyserial（本仓库的
`calib/imu_h7.py` 就是）后，帧长立刻稳定在 82 字节、一致率接近 100%。

> 通用教训：**任何二进制串口协议都不要用 `cat` 或 `readline()` 调试。**
> 要么 pyserial，要么 `stty raw`。

```bash

# 四元数↔欧拉角交叉验证、磁力计是否全零）
python3 ~/calib_ws/calib/imu_h7.py --port /dev/ttyACM0 --seconds 3

# 在代码里用
import sys; sys.path.insert(0, "~/calib_ws/calib")   # 换成绝对路径
from imu_h7 import H7Imu, parse_buffer, validate

with H7Imu("/dev/ttyACM0") as imu:

```

## 6. 仍未解的部分

* **`[4:6]` 这 2 个字节**：每帧变化，取值分布近似随机。三种猜测 ——
  帧校验（CRC16）、包序号、或厂商私有字段。**对做标定没有影响**，
  所以没有继续投入。若你后面拿到厂商上位机或固件源码，可以顺手确认。
* `[6:10]` 两个常量 `0x0091` / `0x002D` 的物理含义不明（可能是设备 ID 与
  协议版本）。同样不影响标定。

## 7. 做 Camera-IMU 标定要特别注意的两点

1. **时间戳用 `t_board_ms`，不要用主机到达时刻。**
   板载时钟是 1 kHz、零丢帧、单调的，比 USB 到达时刻干净得多。
   代价是它和相机时钟（主机单调时钟）之间有一个**未知常量偏移**，
   需要估计——这是 C2 阶段的核心工作之一。

2. **磁力计是废的（恒 0）。**
   所以姿态的 yaw 不可观测，只靠陀螺积分会漂。写程序时不要依赖磁力计，
   配置文件里也不要指望 `m` 通道。
