# 对标 RM 主流做法：差异与优势

> 目标：**不追求"学术新方法"，只要和队里/RM 圈已有做法不同、且效果更好。**
> 本文件用可查证的公开资料还原"主流做法"，再逐项说明我们的差异。
> 结论：**我们的差异集中在"标定目标系的选择"这一条原理级差异上，其余是工程与方法学优势。**

### 1.2 主流做法全貌

**RM 圈的"手眼标定"= 相机 → 云台/枪管 的变换**，不是 相机 → IMU。流程是：

```
① 内参：张正友法 + 棋盘格（OpenCV / MATLAB / ROS camera_calibration）
② 把云台移动到若干个位姿，每个位姿采集一张标定板图
③ T_C_T（板在相机系） ← 由 PnP 得到
   T_B_E（云台在基座系） ← 由电控发来的云台 pitch / yaw 编码器读数得到
④ 解 AX = XB（Tsai-Lenz 或对偶四元数），得到 X = T_E_C（相机 → 云台）
⑤ 非线性优化（Ceres / g2o / OpenCV calibrateHandEye）细化
```

**采集要求**（原文）：位姿 10~30 组、Pitch/Yaw 都要有较大幅度旋转、**相邻位姿相对旋转建议 > 15°**。

### 1.3 三种"简化策略"——很多队实际在用的

原文明确列出：

| 简化 | 做法 |
|---|---|
| **假设旋转对齐** | 若相机光轴与枪管近似平行，直接令 `R_X ≈ I`，只标平移 |
| **实测法** | 用尺子量相机光心到枪管出弹口的 XYZ 偏移，硬构造平移矩阵 |
| **射击验证法** | 固定距离对静态目标射击，按弹着点偏差反向凑参数 |

原文评价：**"这些方法精度有限，在高水平比赛中，严谨的手眼标定仍然是必不可少的。"**

### 1.4 他们自己报告的问题（原文摘录）

> "原来的手眼标定和机械给的参数差得蛮多的，而且自己的**静态误差也大得离谱**，估计距离 8m 的情况下，观察高度为 0.86m 的目标，观测高度为 1.1～1.2m"
> "对比之前的超绝误差有很大进步，虽然目前还不够，但是准备买新标定板了"

**这就是我们要超越的基线。**

## 2. 逐项对比

| 维度 | RM 主流做法 | 我们的做法 | 差异性质 |
|---|---|---|---|
| **标定目标系** | 相机 → **云台/枪管** | 相机 → **IMU** | ⭐ **原理级**（见 §3.1） |
| **运动位姿来源** | 云台 **pitch/yaw 编码器** | 板载 **IMU 陀螺积分** | ⭐ **原理级**（见 §3.1） |
| **自由度覆盖** | 云台 2 轴（pitch/yaw） | 手持 **3 轴任意** | 工程级 |
| **采集方式** | 移动到位 → 静止 → 采集 | **连续运动**（也兼容静态点位） | 工程级 |
| **时间对齐** | **不做**（靠静态点位回避） | **显式估 τ，0.77 ms** | ⭐ 工程级但影响大 |
| **相机时间戳** | 主机接收时刻 | **`DeviceTimestamp` 硬件时间戳** | 工程级 |
| 平移外参 | 尺子量 / 假设 R≈I / 打靶试凑 | **杠杆臂 LS + 残差诊断** | 工程级 |
| 内参 | 张正友 + 棋盘格 | 同上 + **train/val 分离 + 两层合成自检** | 方法学级 |
| 验证指标 | "静态误差大得离谱"（定性） | **误差分解 + 收敛性实验 + 夹具误差量化** | ⭐ 方法学级 |
| 跨组依赖 | 需要电控配合发云台角度话题 | **完全独立**，不需要云台、不需要电控 | 工程级 |

## 3. 我们的差异化优势

### 3.1 ⭐ 差异一（原理级）：标的是 **相机→IMU**，而不是 相机→枪管

**主流为什么标 相机→枪管**：弹道解算最终要的是"目标相对于弹丸出射点的位置"，所以直接标到枪管最直观。

**为什么这有问题**：

$$\text{相机→枪管} \;=\; \underbrace{\text{相机→IMU}}_{\text{可以标定}} \;\times\; \underbrace{\text{IMU→枪管}}_{\text{只能靠 CAD / 尺子}}$$

- 自瞄系统的**姿态来源是 IMU**（云台闭环、目标预测、重力补偿都靠它）；
- 主流做法把 相机→枪管 作为一个整体来标，但**这个变换在系统里并不是一个物理实体**——它要靠 `IMU→枪管` 这段机械参数串起来，而这一段恰恰是**没有传感器、只能靠 CAD 或尺子**的部分；
- 原文说"手眼标定和**机械给的参数**差得蛮多的"——**差的就是这一段**。

**我们的做法**：直接标 **相机→IMU**，把它测到 0.22°。这样：

- 消掉了整条链上**唯一无法标定、只能靠 CAD 的那一段**的不确定度；
- 得到的 `T_IC` 是**闭环里的真实物理量**，可以直接喂给 VIO / 姿态补偿 / 弹道解算；
- 与 RM 的实际用法对齐：**姿态来自 IMU，那外参也应该以 IMU 为基准。**

> 一句话：**主流标的是"相机到枪口"，我们标的是"相机到姿态源"。**

### 3.2 ⭐ 差异二（原理级）：运动位姿来自陀螺，不来自云台编码器

主流方案里，`T_B_E`（云台位姿）由**编码器读数 + 减速比 + 零位标定**推算。这条链上每一环都是误差源：

| 误差源 | 影响 |
|---|---|
| 减速比误差 | 角度按比例错 |
| 零位标定误差 | 恒定角偏置 |
| **齿轮间隙（backlash）** | 换向时角度**不重复**——同一位姿正反转读数不同 |
| 结构挠性 / 联轴器弹性 | 负载下角度偏移 |

这些误差**直接进入 `R_A`**，进而**直接污染 `R_X`**。

**我们的做法**：用板载 1 kHz 陀螺，零偏标定后积分。**中间没有机械环节**——陀螺测的就是角速度本身。

**代价（要诚实说）**：
- 陀螺会漂移（无磁力计 → yaw 不可观测），所以只适合**短时间窗**（标定场景足够）；
- 需要 IMU 与相机刚性固连（这正是我们在做的支架工作）。

**收益**：
- 不受传动链误差影响；
- **不需要云台、不需要电控配合**——相机+IMU 模块可以单独拆下来标，采完再装回云台；
- 三轴任意激励，姿态空间覆盖比两轴云台充分。

### 3.3 差异三（工程级，但影响很大）：显式时间对齐

主流用"移动到位 → 静止 → 采集"来回避时间对齐问题（静止时时间错位不产生误差）。

**但这条回避有两个代价**：

1. **如果没等云台完全停稳就采集**，编码器读数与图像之间仍有时间错位——原文档描述的现象（"静态误差大得离谱"）与这个失效模式**一致**（这是假设，不是结论，值得现场验证）；
2. 拿不到任何**动态**信息，而比赛中的误差恰恰发生在高速跟踪时。

我们做连续运动采集，因此**必须**显式估时钟偏移 τ。实测精度 0.771 ms，折算到 90 °/s 转动下只有 **0.069°** 姿态误差——比验收门槛（1~2°）低一个多数量级。

### 3.4 差异四（工程级）：用相机硬件时间戳

海康 MV-CS020-10UC 支持 `DeviceTimestamp`（1 GHz tick，实测帧间隔精确 10.00 ms）。

**很多队不知道自己的工业相机有这个特性**，一直在用主机接收时刻近似——而主机接收时刻受 USB 调度、系统负载影响，抖动可达毫秒到几十毫秒。我们把它作为 C2 的输入。

### 3.5 ⭐ 差异五（方法学级）：误差可分解、可复现、可解释

主流验证 = 报一个重投影误差，加上"打靶看准不准"。

我们的验证体系：

| 手段 | 回答什么问题 |
|---|---|
| 重投影误差（train/val 分离） | 内参好不好，且**不用标定数据自证** |
| 运动一致性（相对旋转残差） | 外参对不对，实测 0.229° |
| 多解法离散度 | 结果稳不稳，实测 0.185° |
| **两层合成自检** | **误差里有多少是算法的、多少是测试夹具的** |
| **收敛性实验** | 偏差是有限样本方差还是系统偏差 |
| **畸变函数对比** | 内参里高度相关的 `k1/k2/k3` 是否真的对 |

**这套东西的价值不在于"我们更准"，而在于"我们知道自己有多准、以及为什么"。**

### 3.6 ⭐ 差异六（降维打击）：我们能**判定主流简化策略是否成立**

这是我认为最有分量的一条。

主流有三种简化策略（`R_X ≈ I`、尺子量、打靶试凑）。**问题是：没人知道这些简化在本队的具体结构上到底损失了多少精度。**

我们能给：

| 简化策略 | 我们能给出的定量回答 |
|---|---|
| `R_X ≈ I` | 实测 `R_IC` 与单位阵的差角是多少？如果 < 1°，这个简化可接受；如果 > 3°，这个简化就是主要误差源 |
| 尺子量平移 | 杠杆臂 LS 的最优解与尺子值差多少？LS 残差多大？据此判断实测值是否够用 |
| 打靶试凑 | 用标定结果预测弹着点，与实弹对比——我们的误差分解能说明偏差来自外参还是弹道模型 |

**换句话说：我们不只是"也做了一遍标定"，而是能给整个队现有的标定流程做体检。**
这比"我也能标"高一个层次，也更容易在答辩上讲出价值。

## 4. ROS 2 怎么用（本机已有 294 个 `ros-jazzy-*` 包）

本机源里有现成的关键包：

| 包 | 用途 |
|---|---|
| **`ros-jazzy-camera-aravis2`** | **GenICam（含 USB3Vision）相机驱动，直接支持 MV-CS020-10UC**。省掉自研取流，直接出带时间戳的 `sensor_msgs/Image` + `CameraInfo` |
| **`ros-jazzy-camera-calibration`** | ROS 官方相机标定工具，**作为内参的独立第三方对照**（正好满足任务书"与成熟工具对比"） |
| `ros-jazzy-rosbag2` | 录制图像+IMU，**一次采集、多次复算**，数据可复现 |
| `ros-jazzy-message-filters` | `ApproximateTime` 时间同步 |
| `ros-jazzy-image-pipeline` / `cv-bridge` | 图像处理与 ROS↔OpenCV 转换 |

### 建议架构：**主线纯 Python，ROS 2 走旁路做对照**

```
主线（交付物，依赖轻）              旁路（对照与验证）
─────────────────────           ─────────────────────
自研 capture_h7.py               camera_aravis2 节点
  └─ 图像 + IMU + 时间戳            └─ /image_raw + /camera_info
calib/ 全部纯 numpy/scipy/cv2     rosbag2 录制
  └─ C1 / C2 / C3 / C4            camera_calibration 标内参
                                    └─ 与我们的 C1 结果对比 ← "与成熟工具对比"
```

**理由**：
- 交付物**不能绑死在 ROS 上**（任务书要求"使用环境/依赖"写清楚，纯 Python 更好复现、更容易被别人跑起来）；
- 但 ROS 2 是**免费的对照组**，能直接拿下"与成熟工具对比"这一项验证；
- `camera_aravis2` 还能作为我们自研取流代码的**独立验证**（两套实现读同一台相机，时间戳对不对一目了然）。

## 6. 答辩时的对比表述（建议原话）

> "RM 圈通用的手眼标定标的是**相机到云台枪管**，运动位姿来自**云台编码器**，靠移动到位再采集来回避时间对齐。我们做的是**相机到 IMU**——因为自瞄的姿态源就是 IMU，而 相机→枪管 里的 `IMU→枪管` 那一段没有传感器、只能靠 CAD，恰恰是队里反映'和机械参数差得多'的那一段。运动位姿我们改用板载 1 kHz 陀螺积分，绕开了减速比、零位、齿轮间隙这些传动链误差；同时显式估计了时钟偏移 τ 到 0.77 ms。"
>
> "另外，主流有三种简化做法——假设旋转对齐、尺子量平移、打靶试凑。**我们能定量评估这些简化在本队结构上损失了多少精度**，而不只是再做一遍标定。"

**不要说的话**：不要说"我提出了新方法"。每个环节都是已知技术，我们的价值在**目标系选择**、**误差可分解**、和**能给别人做体检**。

## 7. 风险与诚实边界

| 项 | 现状 | 说明 |
|---|---|---|
| 旋转外参 `R_IC` | ✅ 合成数据 0.22° | 待真实数据验证 |
| 时间对齐 τ | ✅ 合成数据 0.771 ms | 待真实数据验证 |
| **平移外参 `t_IC`** | ❌ 未收敛 | 160:1 数值抵消；保底用尺子量 + 声明不确定度 |
| 需不需要云台 | 不需要 | 相机+IMU 模块可独立标定，这是相对主流的实质优势 |
| 陀螺漂移 | 只适合短窗 | 标定场景足够；不能拿它做长时导航 |
