## 1.3 标定在整个 RM 算法中的位置

标定是**离线做一次**的工作，做完之后那些数字就固定下来，比赛时不再使用标定板：

```
【离线，只做一次】
  标定板 → 解出：内参 fx/fy/cx/cy + 畸变
                外参 R_IC / t_IC
                时间偏移 τ
                     ↓ 写进代码，固定下来

【在线，比赛每一帧】
  识别算法检测装甲板 → 像素坐标 (u, v)
       ↓ 用已标定的内参    像素 → 方向
       ↓ 用已标定的外参    相机系 → IMU 系
       ↓ 用已标定的时间偏移 对齐到正确时刻
       ↓ 结合 IMU 姿态
  云台要转多少度 → 电机执行
```

**识别算法负责"目标在哪"，标定负责"那个位置对应的角度是多少"，两者串联，缺一不可。**

标定板的作用是**一把尺子** —— 它给相机一组"已知精确 3D 位置"的点，用来反推相机的运动。它本身不是要被识别的东西。

# 二、系统实现

按提交要求，分三部分说明：**① 硬件数据如何读取 ② 具体算法实现 ③ 算法输出什么**。

## 2.1 ① 硬件数据如何读取

本任务的两个传感器**都不能用常规方式读取**，这是实现中最先要解决的问题。

### 2.1.1 相机：海康 MV-CS020-10UC

| 项 | 值 |
|---|---|
| 接口 | **USB3 Vision（U3V）—— 不是 UVC** |
| 分辨率 | 1624×1240，Mono8 |
| 帧率 | 10 fps |
| 时间戳 | 相机内置 `DeviceTimestamp`，**1 GHz** |

**关键点：USB3 Vision 不是 UVC 协议。**

这意味着 `cv2.VideoCapture(0)` **读不到这台相机**（UVC 才走 V4L2），必须走厂商的 GenICam 协议栈。

实现上做了两层抽象：`HikCamera`（U3V，走 aravis）与 `UvcCamera`（普通 UVC，走 OpenCV），统一到 `CameraBase` 接口。保留 UVC 分支是为了在没有工业相机时仍能跑通整条管线。

**踩过的三个坑：**

| 现象 | 根因 | 处理 |
|---|---|---|
| 进程随机 `SIGABRT`（`corrupted size vs. prev_size`）| `np.frombuffer` 零拷贝取图，底层 buffer 被 GC 后悬空指针（use-after-free）| 改为强制拷贝 |
| 连续开关 5 次后相机"假死"，报 `LIBUSB_ERROR_BUSY` | 非正常释放导致 USB 端点未复位 | 检测到 wedge 签名后自动做 USB reset |
| `read_exposure()` 报错 | 调了不存在的方法 `is_exposure_time_auto()` | 改用正确接口 |

### 2.1.2 IMU：H7_IMU_With_EKF

| 项 | 值 |
|---|---|
| USB VID:PID | `0483:6666` |
| 帧长 | **82 字节**，同步头 `5A A5` |
| 频率 | **1000.000 Hz** |
| 时间戳 | 板载 `t_board_ms` |

帧结构：偏移 14 为 `t_board_ms`，18 为加速度，30 为角速度，42 为磁力计，66 为四元数。

**关键实测结论：磁力计恒为 0 → yaw 不可观测。**

这直接决定了后续算法设计：**所有用到旋转的地方只用角速度积分，绝不依赖磁力计或绝对航向。**

### 2.1.3 两个时钟不同源 —— 这是 C2 存在的理由

相机时间戳来自相机内部 1 GHz 计数器，IMU 时间戳来自 STM32 板载毫秒计数器，**两者没有共同时间基准，且存在固定偏移 τ**。

> 这就是 **C2 时间对齐**要估的量。它在物理上真实存在，不是可选步骤。

> ⚠️ **重要教训**：在解析公开数据集（ROS bag）时发现，bag 的**录制时间**与消息头里的**真实采样时间**完全不同 ——
> 前者步长标准差达 **±14647 µs**（完全混乱），后者仅 **±0.1 µs**（精确 200 Hz）。
> 用错时间戳会让 C2 彻底失效、C3 全废，**而且不会报错**。

## 2.2 ② 具体算法实现

### 2.2.1 总体：四步管线

```
C0 采集         C1 内参          C2 时间对齐       C3 外参          C4 验证
────────  →  ────────────  →  ─────────────  →  ────────────  →  ──────────
图 + IMU      fx fy cx cy       τ（时钟偏移）     R_IC, t_IC       误差报告
              畸变系数                                              + 自检
```

各步代码位置：`intrinsics.py`(293行) / `sync.py`(427行) / `extrinsics.py`(605行) / `validate.py`(362行)，
另有共用的 `target_detect.py`(473行) 和 `trajectory.py`(305行)。

### 2.2.2 C1 · 相机内参标定

**做法**：张正友标定法 + Brown-Conrady 畸变模型，用 `cv2.calibrateCamera`（Levenberg-Marquardt 非线性最小二乘，张正友闭式解给初值）。

**关键实现细节：**

- 用 `findChessboardCornersSB`（sector-based，绕点一圈数黑白交替 4 次 + 网格拓扑验证），并**禁止回退到经典版**（经典版慢 684 ms 且更差）
- 角点做 `cornerSubPix` 亚像素精化 —— 内参精度直接取决于角点定位精度
- **校正角点顺序约定**：约定不一致会让重投影从 0.13 px 恶化到 **108.8 px**

### 2.2.3 C2 · 相机-IMU 时间对齐

**做法（角度匹配，与坐标系无关）：**

1. 相机侧：把每帧 PnP 位姿拟合成 **B 样条连续轨迹**，解析求导得角速度
2. IMU 侧：陀螺积分得角度曲线
3. 在 τ 搜索范围内找让两条角度曲线最吻合的 τ

**为什么用角度而不是直接比角速度**：角度是角速度的积分，对高频噪声有平滑作用；且两条角度曲线的**相对平移量就是 τ**，曲线越陡（转得越快）τ 越准。

**关键实现细节：**

- **静止段检测先做中位滤波去尖峰**。实测 IMU 每秒有一个孤立单帧尖峰（如 `[1.44 1.45 15.33 1.79 1.89]`），滚动标准差被撑爆 → 真静止被判成运动 → 零偏标定整个放弃。去尖峰后恢复 **6901 帧 = 6.9 s**
- 零偏用**中位数**而非均值，对残余尖峰鲁棒
- **10 kHz 累积陀螺积分**提高时间分辨率

### 2.2.4 C3 · Camera-IMU 外参

输出 `T_IC`（相机系 C → IMU 系 I）：`p_I = R_IC · p_C + t_IC`。

**旋转部分**：用手眼标定方程 AX = XB，`cv2.calibrateHandEye` 的**四种解法全跑 + 一致性聚类投票**，而不是只用一种。不同解法对噪声敏感度不同，四种结果聚在一起说明解可信，散开则说明数据有问题 —— 这本身就是数据质量判据。

**平移部分**：比旋转难得多，因为 `t_IC` 只在**相机有旋转**时才在加速度计上可观测（旋转木马效应：离旋转轴越远，离心/切向加速度越大）。采用的手段：

| 手段 | 作用 |
|---|---|
| B 样条解析求导 | 得角加速度和向心加速度，避免数值差分放大噪声 |
| **联合估计重力方向** | 重力与杠杆臂耦合，分开估会互相污染 |
| Huber IRLS | 抑制离群帧 |
| 截断式离群剔除 | 剔除残余大残差帧 |
| Allan 方差 | 分析 IMU 噪声特性，为权重提供依据 |
| Bootstrap | 给出参数置信区间 |
| 交叉验证 | 检查是否过拟合 |

### 2.2.5 靶标检测

支持三种靶标，**切换靶标不需要改算法**：

| 靶标 | 状态 | 用途 |
|---|---|---|
| **棋盘格** | ✅ 主力 | 角点精度最高（两直线求交 + 亚像素）|
| **ChArUco** | ✅ 已实现 | 抗遮挡版棋盘格（带唯一 ID）|
| **AprilGrid** | ✅ 已实现 | 用于跑公开数据集 |

**为什么要有 ChArUco**：棋盘格有一个根本性缺陷 —— **180° 中心对称二义性**，平面 PnP 因此存在两解。ChArUco 每个方块有 ID，可根治。

**AprilGrid 是后期为验证而加的**：公开的相机-IMU 数据集几乎都用 AprilGrid（每个 tag 有唯一编号，对运动模糊和部分遮挡鲁棒得多）。

### 2.2.6 配置不硬编码

所有参数（靶标尺寸、相机参数、IMU 参数、算法超参）集中在 `config/calibration.yaml`，代码里没有硬编码常量。

## 2.3 ③ 算法输出什么

### 2.3.1 输出文件

一条命令生成两种格式（内容相同）：`results/calibration_result.yaml`（人读）与 `.json`（程序读）。

### 2.3.2 输出内容

| 分组 | 内容 |
|---|---|
| **C1 内参** | `camera_matrix`（fx, fy, cx, cy）、`dist_coeffs`（k1,k2,p1,p2,k3）、`image_size`、重投影残差 |
| **C2 时间对齐** | `tau_s` 时钟偏移（秒）|
| **C3 外参** | `R_IC`（3×3 旋转）、`t_IC`（平移）、`T_IC`（4×4 齐次矩阵）|
| **C4 验证** | 重投影残差、交叉验证残差、运动一致性、`\|g\|` 内建自检、Bootstrap 置信区间 |

### 2.3.3 每一项怎么被下游用

| 输出 | 比赛时怎么用 |
|---|---|
| `camera_matrix` + `dist_coeffs` | 像素坐标 → 相机坐标系方向（去畸变 + 反投影）|
| `R_IC` | 相机系方向 → IMU 系方向 |
| `t_IC` | 修正杠杆臂：相机不在 IMU 原点，旋转会带来额外位移 |
| `tau_s` | 把图像时间戳对齐到 IMU 时间轴，**否则姿态数据用错时刻** |

### 2.3.4 坐标系定义

**任务文档 3.2 与验收第 8 条明确要求说明此项。** `T_IC` 表示相机系 C 到 IMU 系 I 的变换：`p_I = R_IC · p_C + t_IC`。

> ⚠️ **与 Kalibr 的约定相反**。Kalibr 的 `T_cam_imu` 是反方向，对照时必须转置，否则会得到一个"看起来合理但完全错误"的结果。

## 3.2 外部真实数据 · 相机内参 —— 验证通过

用 OpenCV 官方样例图集（left01–14 / right01–14，真实相机拍摄）做基准测试。
为确保公平，**比的是投影函数而非单个畸变系数**（系数之间强相关，逐项比会得出错误结论）。

设计三条**互相自洽、不依赖任何外部参考值**的判据：

| 判据 | 含义 |
|---|---|
| ① 重投影残差 | 用该 K/dist 反解每帧位姿后的拟合能力 |
| ② 畸变外推合理性 | 径向畸变倍率在拟合区外应平缓；爆到几十倍即高阶过拟合 |
| ③ **去畸变后直线直不直** | 最硬 —— 不关心参数长什么样，只看结果对不对 |

**实测（我们 vs ROS `camera_calibration`）：**

| 判据 | 数据集 | 我们 | ROS |
|---|---|---|---|
| ① 重投影 px | left / right / all | **0.233 / 0.231 / 0.268** | 0.641 / 0.710 / 0.599 |
| ② 畸变外推 | left / right / all | **6.8 / 3.1 / 5.7** | 66.7 / 26.3 / 30.0 |
| ③ 直线残差 px | left / right / all | **0.067 / 0.064 / 0.075** | 0.193 / 0.195 / 0.137 |

**三项判据 × 三个数据集 = 九次对比，全部优于 ROS 官方实现。** 验证集重投影误差 0.20 ~ 0.30 px。

# 四、遇到的问题

## 问题 1：学习门槛

第一次接触计算机视觉和机器人操作系统，对一些库、已有算法和工具的学习有困难。目前大概知道某个东西能干什么，具体怎么干还依赖 agent。

## 问题 2：真实数据采集失败

目前只做到了识别标定板这一步，后续联合标定的数据采集没做成。原因是可以量化的：

| 要求 | 实测 | 差距 |
|---|---|---|
| 起始 ≥3 s **完全静止** | 仍有 **5~6 °/s** 角速度 | 人手无法完全静止 |
| 深度跨度 ≥ **2×** | 仅 **1.09×** | 不足 |
| 标定板检测率 | **24%**（光照不足）| 不足 |

**更根本的一点**：相机和 IMU 必须**刚性固连**，手持会让两者的相对位置发生变化，**标定的前提条件就被破坏了**。

**结论**：这套采集需要**刚性支架 + 云台 + 补光**，不是靠多试几次能解决的。

## 问题 3：数据路线走得不顺

前期在数据采集的基础设施（相机和 IMU 的驱动、显示、稳定性）上投入比较多，压缩了后期算法验证的时间。

# 五、心得

## 5.1 要多花时间

用 agent 可以提高效率、解决一些问题，但**不会很快增长知识**，很多东西还是得自己啃。

## 5.2 一开始最好不要只走一条路

真实数据采集和用网上数据做验证应该**同时进行**，一个交给 agent 自动化跑，一个靠自己动手，这样哪条路走不通都还有另一条。这一点一开始和 AI 讨论怎么完成这个任务时它就提过，当时没有足够重视。

## 5.3 标定需要的真实数据，不是人手的精度能做出来的

这次亲身试过之后才真正理解。

## 5.4 算法是有适用边界的，选技术路线之前要想清楚

我们的方法属于**分步几何标定**：先从靶标解相机位姿，再拿位姿去比较旋转，所以对**单帧位姿精度**很敏感。

而 Kalibr、Basalt 这类做的是**批量优化**，位姿、内参、外参、时间偏移一起优化，噪声可以在优化过程中被平均掉，能容忍更差的检测。

实测下来，靶标在画面里只有几十像素、每帧只能检出 2~12 个标记时，单帧位姿噪声有 2~3 度，而相邻帧真实转角只有 0.6 度左右，**信噪比不到 1，方法就失效了**。这也解释了为什么公开数据集都是给批量优化方法设计的。

## 5.5 "能判断结果对不对"是独立的能力

这是我这次体会最深的一点。验证阶段的三次异常——判据在不同数据集上数值完全相同、残差小得不合理、角速率与陀螺差 15 倍——**都是先起疑才查出来的**。如果无条件接受工具输出，这些错误会被当成"验证通过"。

# 六、不足与下一步

## 6.1 不足

1. **核心链路未闭环**：识别标定板已打通，但 Camera-IMU 外参尚未在真实数据上跑出合格结果
2. **对公开数据集适配不足**：我们的分步方法需要"靶标大而清晰"的数据，而主流 Vi 数据集是为批量优化方法设计的
3. **个人投入时间不够**：前期侧重基础设施，后期收尾紧张

## 6.2 下一步

1. **解决采集硬件**：向战队申请刚性支架、云台、补光灯
2. **提高靶标检测精度**：加时序跟踪，用多帧约束压制单帧位姿噪声
3. **补强验证**：用公开数据集自带的真值位姿单独验证 C2，把"位姿误差"与"时间对齐误差"解耦
4. **长期**：为平移外参引入批量优化（借鉴 Kalibr 的思路），提高对低质量数据的容忍度
