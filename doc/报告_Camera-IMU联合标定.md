# 四、系统实现

## 4.1 ① 硬件数据如何读取

### 4.1.1 相机：海康 MV-CS020-10UC

| 项 | 值 |
|---|---|
| 接口 | **USB3 Vision（U3V）** |
| 分辨率 | 1624×1240，Mono8 |
| 帧率 | 10 fps |
| 时间戳 | 相机内置 `DeviceTimestamp`，1 GHz |

**关键点：USB3 Vision 不是 UVC 协议**，所以 `cv2.VideoCapture` 读不到这台相机，必须走 GenICam 协议栈。

实现上做了两层抽象：`HikCamera`（U3V，走 aravis）与 `UvcCamera`（普通 UVC，走 OpenCV），统一到同一个 `CameraBase` 接口。保留 UVC 分支是为了在没有工业相机时仍能跑通整条管线。

### 4.1.2 IMU：H7_IMU_With_EKF

| 项 | 值 |
|---|---|
| USB VID:PID | `0483:6666` |
| 接口 | 串口（CDC） |
| 帧长 | 82 字节，同步头 `5A A5` |
| 频率 | 1000 Hz |
| 时间戳 | 板载 `t_board_ms` |

**帧结构**（偏移单位：字节）：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 2 | 同步头 `5A A5` |
| 2 | 2 | 帧长 |
| 14 | 4 | `t_board_ms` 板载时间戳 |
| 18 | 12 | 加速度 x, y, z |
| 30 | 12 | 角速度 x, y, z |
| 42 | 12 | 磁力计 x, y, z |
| 66 | 16 | 四元数 w, x, y, z |

**实测结论：磁力计恒为 0，yaw 不可观测。** 这直接决定了算法设计：所有用到旋转的地方只用角速度积分，不依赖磁力计或绝对航向。

### 4.1.3 两个时钟不同源

相机时间戳来自相机内部 1 GHz 计数器，IMU 时间戳来自 STM32 板载毫秒计数器，两者没有共同时间基准，存在固定偏移 τ。**这就是 C2 时间对齐要估的量。**

## 4.2 ② 具体算法实现

### 4.2.1 总体：四步管线

```
C0 采集         C1 内参          C2 时间对齐       C3 外参          C4 验证
────────  →  ────────────  →  ─────────────  →  ────────────  →  ──────────
图 + IMU      fx fy cx cy       τ（时钟偏移）     R_IC, t_IC       误差报告
              畸变系数                                              + 自检
```

代码位置：`intrinsics.py`(293行) / `sync.py`(427行) / `extrinsics.py`(605行) / `validate.py`(362行)，
共用的 `target_detect.py`(473行) 与 `trajectory.py`(305行)。

### 4.2.2 C1 · 相机内参标定

采用**张正友标定法 + Brown-Conrady 畸变模型**，用 `cv2.calibrateCamera` 做 Levenberg-Marquardt 非线性最小二乘，初值由张正友闭式解给出。

角点检测用 `findChessboardCornersSB`，再做 `cornerSubPix` 亚像素精化 —— 内参精度直接取决于角点定位精度。

### 4.2.3 C2 · 相机-IMU 时间对齐

采用**角度匹配**方法，与坐标系无关：

1. 相机侧：把每帧 PnP 位姿拟合成 **B 样条连续轨迹**，解析求导得角速度
2. IMU 侧：陀螺积分得角度曲线
3. 在 τ 搜索范围内，找让两条角度曲线最吻合的 τ

**为什么用角度而不是直接比角速度**：角度是角速度的积分，对高频噪声有平滑作用；两条角度曲线的相对平移量就是 τ，曲线越陡（转得越快）τ 越准。

实现上还做了：陀螺累积积分提高时间分辨率；静止段检测中先做中位滤波去除孤立尖峰，再用中位数估计零偏（对残余尖峰鲁棒）。

### 4.2.4 C3 · Camera-IMU 外参

输出 `T_IC`（相机系 C → IMU 系 I）：`p_I = R_IC · p_C + t_IC`。

**旋转部分**：解手眼标定方程 AX = XB，用 `cv2.calibrateHandEye` 的**四种解法（TSAI / PARK / HORAUD / DANIILIDIS）全跑，再做一致性聚类投票**。不同解法对噪声敏感度不同，四种结果聚在一起说明解可信，散开则说明数据有问题。

**平移部分**：`t_IC` 只在**相机有旋转**时才在加速度计上可观测（离旋转轴越远，离心/切向加速度越大）。采用的手段：

| 手段 | 作用 |
|---|---|
| B 样条解析求导 | 得角加速度和向心加速度，避免数值差分放大噪声 |
| 联合估计重力方向 | 重力与杠杆臂耦合，分开估会互相污染 |
| Huber IRLS | 抑制离群帧 |
| 截断式离群剔除 | 剔除残余大残差帧 |
| Allan 方差 | 分析 IMU 噪声特性，为权重提供依据 |
| Bootstrap | 给出参数置信区间 |
| 交叉验证 | 检查是否过拟合 |

### 4.2.5 靶标检测

支持三种靶标，**切换靶标不需要改算法**：

| 靶标 | 状态 | 用途 |
|---|---|---|
| 棋盘格 | ✅ 主力 | 角点精度最高（两直线求交 + 亚像素）|
| ChArUco | ✅ 已实现 | 抗遮挡版棋盘格（带唯一 ID）|
| AprilGrid | ✅ 已实现 | 用于跑公开数据集 |

棋盘格有一个固有缺陷 —— **180° 中心对称二义性**，平面 PnP 因此存在两解；ChArUco 每个方块有 ID，可以根治。AprilGrid 则是公开相机-IMU 数据集的主流靶标（每个 tag 有唯一编号，对运动模糊和部分遮挡鲁棒）。

### 4.2.6 配置不硬编码

所有参数（靶标尺寸、相机参数、IMU 参数、算法超参）集中在 `config/calibration.yaml`，代码里没有硬编码常量。

## 4.3 ③ 算法输出什么

### 4.3.1 输出文件

一条命令生成两种格式（内容相同）：`results/calibration_result.yaml`（人读）与 `.json`（程序读）。

### 4.3.2 输出内容

| 分组 | 内容 |
|---|---|
| **C1 内参** | `camera_matrix`（fx, fy, cx, cy）、`dist_coeffs`（k1,k2,p1,p2,k3）、`image_size`、重投影残差 |
| **C2 时间对齐** | `tau_s` 时钟偏移（秒）|
| **C3 外参** | `R_IC`（3×3 旋转）、`t_IC`（平移）、`T_IC`（4×4 齐次矩阵）|
| **C4 验证** | 重投影残差、交叉验证残差、运动一致性、`|g|` 内建自检、Bootstrap 置信区间 |

### 4.3.3 每一项怎么被下游用

| 输出 | 比赛时怎么用 |
|---|---|
| `camera_matrix` + `dist_coeffs` | 像素坐标 → 相机坐标系方向（去畸变 + 反投影）|
| `R_IC` | 相机系方向 → IMU 系方向 |
| `t_IC` | 修正杠杆臂：相机不在 IMU 原点，旋转会带来额外位移 |
| `tau_s` | 把图像时间戳对齐到 IMU 时间轴，否则姿态数据用错时刻 |

### 4.3.4 坐标系定义

**任务文档 3.2 与验收第 8 条明确要求说明此项。** `T_IC` 表示相机系 C 到 IMU 系 I 的变换：`p_I = R_IC · p_C + t_IC`。

注意这与 Kalibr 的约定相反（Kalibr 的 `T_cam_imu` 是反方向），对照时必须转置。

# 六、算法适用范围

> 本章回答两个问题：**什么条件下标定是可行的，什么条件下不可行。**
> 所有结论都来自本项目的实测数据，不是推测。

## 6.1 总的判断

本方法属于**分步几何标定**：先从靶标解出每帧相机位姿，再用位姿序列去和时间对齐、外参作比较。

因此它有一个**硬性前提**：

> **必须存在足够多的帧，能在每一帧上高精度地解出相机位姿。**

下面所有"可行 / 不可行"的条件，都是从这个前提出发的。

## 6.2 可行条件（合成数据实测）

在受控的合成数据上，各环节都达到预期精度：

| 条件 | 要求 | 实测 | 结果 |
|---|---|---|---|
| 靶标清晰完整 | 每帧可见完整网格 | 88 个角点全检出 | ✅ |
| 内参可辨识 | 靶标有倾角变化 | — | fx 误差 0.2% |
| `fx` | — | **1102.07**（真值 1100）| ✅ |
| 旋转外参 | — | 误差 **0.222°** | ✅ |
| 平移外参 | — | 误差 **0.54 ~ 0.68 cm** | ✅ |
| 时间偏移 τ | — | 误差 **0.771 ms** | ✅ |
| `|g|` 自检 | ≈ 9.80665 | **9.8016** | ✅ |

**外部真实图像（相机内参）同样验证通过**：OpenCV 官方样例图集，三项自洽判据 × 三个数据集共九次对比，全部优于 ROS 官方实现，验证集重投影误差 **0.20 ~ 0.30 px**。

## 6.3 不可行情形（真实采集实测）

### 6.3.1 相机与 IMU 非刚性固连 —— 最致命

这是本次真实采集失败的根本原因。

**标定的前提是相机与 IMU 的相对位姿恒定。** 手持标定板或手持相机时，
两者之间会引入额外的相对运动，**这个前提直接被破坏**，任何后续计算都失去意义。

**结论**：相机与 IMU **必须机械固定**（同一支架或同一云台）。

### 6.3.2 靶标运动不符合假设

标准方法假设**标定板静止**，相机运动。手持标定板时实测：

| 项 | 要求 | 实测（session_02）| 后果 |
|---|---|---|---|
| 起始静止段 | ≥3 s 完全静止 | 仍有 **5~6 °/s** 角速度 | 零偏标定不可用 |
| 旋转激励 | 建议 ≥90 °/s | 仅 **30 ~ 36 °/s** | τ 精度不足 |
| 深度跨度 | ≥2× | **1.09×**（板视尺寸 76→82 px）| 内参不可辨识 |

同批数据（session_01）的症状更明确：

| 症状 | 实测 | 说明 |
|---|---|---|
| 深度跨度 | 1.28× | 仍不足 2× |
| 内参退化 | `fx = 3766`、`k3 = 107` | 明显过拟合，物理上无意义 |
| 时间偏移 τ | −0.5 s（**撞搜索边界**）| 根本没找到解 |
| 运动一致性 | 27.9°（64 对中 8 对 >90°）| 平面 PnP 二义性导致翻转 |
| 重力自检偏差 | 0.355 | 应 ≈ 0 |

### 6.3.3 靶标检测率不足

| 数据来源 | 检测率 / 每帧可用标记数 |
|---|---|
| session_01（真实）| 35% |
| session_02（真实）| **24%**（光照不足，59/122 帧全图均值 <40）|
| Monado MIC11（Valve Index）| 全 1705 帧**最多 11 个**标记，中位数 3 |
| Monado MGC23（Reverb G2）| 中位数 **0**，最多 1 |
| EuRoC MH_01 | 整段 187 s **无靶标**（标定是单独采集的）|

Monado 的标记数分布更能说明问题 —— **没有"甜点区"**：

```
   0 ~  3 个标记:  836 帧 (49.1%)
   3 ~  6 个标记:  543 帧 (31.8%)
   6 ~ 10 个标记:  307 帧 (18.0%)
  10 ~ 12 个标记:   19 帧 ( 1.1%)   ← 全数据集最好也只有 11~12 个
  15+ 个标记:        0 帧
```

靶标太远则标记太小，太近则只有少数标记在画面内。

## 6.4 根本原因：信噪比

上述现象可以用**一个量**统一解释。

时间偏移的估计精度近似为：

> **Δτ ≈ Δθ / ω**
>
> · `Δθ` = 单帧位姿的角度误差 —— 本项目实测 **2 ~ 3°**
> · `ω` = 相机真实角速度 —— 本项目实测约 **32 °/s**

其中 `Δθ` 是单帧位姿的角度误差，`ω` 是相机真实角速度。**转得越慢，同样的位姿误差造成的 τ 误差越大。**

代入实测数字：

| 量 | 值 | 来源 |
|---|---|---|
| 单帧位姿角度误差 `Δθ` | **2 ~ 3°** | 每帧仅 2~12 个标记时的 PnP 精度 |
| 相邻帧真实转角 `ω·Δt` | **约 0.6°** | 角速度 32 °/s × 帧间隔 18.5 ms |
| **信噪比** | **< 1** | 误差比信号还大 |

**当信噪比小于 1 时，相邻帧的相对旋转完全被噪声淹没，C2 与 C3 都无法工作。**

作为对照，我用**三个互相独立的来源**测量同一段数据的角速度，确认了"真实运动确实很慢"：

| 来源 | 角速度中位数 | 说明 |
|---|---|---|
| 真值轨迹（lighthouse 独立追踪）| **31.9 °/s** | 与相机、IMU 均无关 |
| 陀螺 | **32.3 °/s** | 与真值比值 **0.99** |
| 图像相位相关 | **21 °/s** | 第三种独立的图像测量 |

这也解释了**为什么主流公开数据集都是给批量优化方法设计的**：

| | 分步几何（本方法）| 批量优化（Kalibr / Basalt）|
|---|---|---|
| 对单帧位姿精度 | **敏感** | 不敏感 |
| 噪声处理 | 事后加权 / 剔除 | **在优化中被平均掉** |
| 靶标可见性要求 | 高 | 低（可部分遮挡、可模糊）|
| 适用数据 | 靶标大而清晰的受控采集 | 剧烈运动、模糊、遮挡的野外数据 |

## 6.5 小结：一张对照表

| 条件 | 可行 | 不可行 |
|---|---|---|
| 相机-IMU 连接 | **刚性机械固定** | 手持、软连接 |
| 标定板 | **完全静止**（或运动可被测量）| 手持且运动未知 |
| 旋转激励 | ≥ 90 °/s | < 40 °/s |
| 深度跨度 | ≥ 2× | < 1.5× |
| 靶标可见性 | 每帧完整清晰、检测率 > 80% | 检测率 < 50%，每帧仅数个标记 |
| 光照 | 充足（全图均值 ≫ 40）| 偏暗 |
| 起始静止段 | 能稳定检出 ≥3 s | 检不出静止段 |

# 七、不足与下一步

## 7.1 不足

1. **核心链路未闭环**：识别标定板已打通，但 Camera-IMU 外参尚未在真实数据上跑出合格结果
2. **对公开数据集适配不足**：分步方法需要"靶标大而清晰"的数据，而主流 Vi 数据集是为批量优化方法设计的
3. **个人投入时间不够**：前期侧重基础设施，后期收尾紧张

## 7.2 下一步

1. **解决采集硬件**：向战队申请刚性支架、云台、补光灯
2. **提高靶标检测精度**：加时序跟踪，用多帧约束压制单帧位姿噪声
3. **补强验证**：用公开数据集自带的真值位姿单独验证 C2，把"位姿误差"与"时间对齐误差"解耦
4. **长期**：为平移外参引入批量优化（借鉴 Kalibr 的思路），提高对低质量数据的容忍度
