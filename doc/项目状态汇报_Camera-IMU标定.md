## 4. 阻塞项与解决方法

### 4.1 平移外参 t_IC（唯一未通过项）

#### 现象

杠杆臂 LS 残差 **11.1 m/s²**（≈ g），解出的 `|t_IC| = 3.23 m`，而真值是 **4.25 cm**。

#### 根本原因：160:1 的数值抵消

已验证**方程本身完全正确**——用真值代入，`R̈_WC·r` 与 `R_WI·a_meas + g_W − a_WC` 之差是 **4e-15**，最小二乘能精确还原 r。

问题在于这一项的量级：

```
|R_WI · a_meas|  = 9.82  m/s²      ← 加速度计量到的是重力
|b|              = 0.059 m/s²      ← 相减之后剩下的、真正含杠杆臂信息的量
                                     ↓ 160 : 1 的抵消
```

**b 是两个 9.8 量级的量相减后剩下的 0.06。** 对输入的微小误差极度敏感。

而 `a_WC`（相机加速度）目前是靠**对 PnP 解出的相机位置做二阶数值微分**得到的。平面标定板的**深度方向可观测性天生就差**，深度噪声被二阶微分放大后，直接把 0.06 的信号淹没了。

**这不是算法写错，是这个输入量在当前条件下不够干净。**

#### 解决方法（三条路，按成本排序）

| 方案 | 做法 | 成本 | 预期效果 | 建议 |
|---|---|---|---|---|
| **A. 退保底方案** | 用**尺子量**相机光心到 IMU 中心的距离，在报告里**明确声明不确定度**（如 "|t_IC| = 4.3 ± 0.3 cm，由游标卡尺测量"） | 1 小时 | 完全可交付 | ✅ **先做这个** |
| **B. 改善观测条件** | ① 相机帧率提到 **50~100 Hz**（二阶微分噪声 ∝ 1/Δt²，5 倍帧率 → 噪声降 25 倍）；② 采集时**剧烈快速旋转**，让 R̈·r 项远大于平移加速度项 | 半天（含采集） | 有希望收敛到 cm 级 | ✅ 与 A 并行 |
| **C. 上 Kalibr** | 用成熟工具做**全批量优化**（IMU 预积分 + 相机位姿 + 外参联合估计），避免任何显式数值微分 | 2~3 天 | 最可靠，且顺带满足"与成熟工具对比"这项验证 | 时间够就做 |

> **方案 A 为什么不是"作弊"**：任务书只要求"输出 \(t_{IC}\)"和"说明标定结果是否合理以及判断依据"。一个**来源可追溯、不确定度明确**的尺子测量值，在工程上比一个来源不明、量级离谱的优化输出要诚实得多。
> 而且这正好可以写进报告：**"我们实现了杠杆臂 LS，但实测其数值条件数为 160:1、在当前相机帧率下不可收敛；因此最终采用实测值并给出不确定度，同时把 LS 的失败过程作为验证章节的一部分。"** —— 这比"跑出来一个数"有说服力得多。

#### 我下一步会做的

先把**方案 B 在合成数据上验证**：把仿真相机帧率提到 100 Hz，确认杠杆臂 LS 能收敛。如果能，这条路就确定了；如果不能，说明还需要方案 C。**这一步不需要硬件，我现在就能做。**

### 4.3 硬件刚性固定（进行中）

这是 `T_IC` 是常数的**前提**。一旦相对位置在采集过程中变化，后面全部作废。

**关键要求：**

| 要求 | 说明 |
|---|---|
| **刚性** | 铝板 / 3D 打印支架。**不要**用泡棉、魔术贴、橡皮筋——会蠕变 |
| **线缆应力释放** | USB 线拉扯 IMU 是最常见的隐性松动源。用扎带把线固定在**支架**上，而不是让它悬着拽 IMU |
| **基线 2~10 cm** | 太小 → 杠杆臂信噪比差；太大 → 两者运动差异大且不便安装 |
| **做记号** | 在支架上刻线/点漆，以后能复位到同一位置，保证结果可复现 |
| **采集后复查** | 采完再拍一张标定板图，和开头对比角点位置；有明显位移说明中途松了，数据作废 |

> **一个建议**：RoboMaster 里相机和 IMU 本来就都装在云台上。**如果直接标定实际云台总成，标出来的外参就是场上要用的那组**，还省了做支架。值得考虑。

## 5. 过程中发现的问题（建议写进报告，属于加分项）

这些都是**不会报错、只会悄悄错**的类型，比"跑通"更有汇报价值：

| # | 问题 | 后果 | 解决 |
|---|---|---|---|
| 1 | **平面标定板 PnP 二义性** | `SOLVEPNP_IPPE` 在本数据上 **120/120 全部"成功"，但旋转误差 179.67°、位置误差 2.58 m**。内参不受影响（所以 C1 照样通过），但相机轨迹整体翻转，C2/C3 全崩 | 封装 `solve_pnp_board`：IPPE 给两个分支 → **各自 LM 细化** → 按"板面朝向相机 + 时间连续"选分支。**只做 IPPE 不细化，残差会从 0.6° 涨到 8.9°** |
| 2 | **`calibrateHandEye` 约定** | `R_gripper2base` 要传 `R_WI` 本身，传 `R_WI.T` 会让所有方法**一致地**错几十度且不报错 | 用真值数据把约定卡一遍（自检第 ② 项） |
| 3 | **陀螺无绝对 yaw** | "运动一致性"若写成比较**绝对姿态**，指标会凭空多出几十度 | 必须用**相对旋转**形式 `R_WI(2)ᵀ R_WI(1) = R_IC·[R_CB(2)R_CB(1)ᵀ]·R_ICᵀ`，它与坐标系朝向无关 |
| 4 | **个别求解器返回非法解** | DANIILIDIS 在平移输入退化时返回非正交阵，直接平均会把 `R_IC` 拖偏 **22°**（而三项有效方法之间只差 0.065°） | 先筛合法旋转矩阵，再取**最大一致簇** |
| 5 | **`cat` 读二进制串口** | tty 行规程篡改字节，帧长看起来在 76~100 字节抖动，误判为变长协议 | 必须 pyserial / `stty raw` |
| 6 | **硬件"时好时坏"** | 相机报 `USB3Vision write_memory timeout`，一度怀疑是 aravis 不兼容 | **换了一个 USB 口就全好了**。寄存器读写时好时坏 + 取流超时，先怀疑线缆/供电/主控口 |
| 7 | **U3V 相机不能用 OpenCV 打开** | 三个接口全是 USB3 Vision，没有 UVC 类 | 走 aravis；OpenCV 只适用于 `--camera-source uvc` |

## 6. 数据格式与坐标系约定（交付要求项，已锁定）

### 6.1 坐标系

| 系 | 定义 |
|---|---|
| `C` 相机系 | 原点在光心；x 向右、y 向下、z 沿光轴向前（OpenCV 约定） |
| `I` IMU 系 | 原点在 IMU 测量中心；**实测 z 轴朝上**（静止时 `az ≈ +9.77`） |
| `B` 标定板系 | 原点在棋盘格左上角第一个内角点；z 垂直板面向外 |

### 6.2 外参约定（**必须写进报告**）

$$T_{IC}=\begin{bmatrix}R_{IC}&t_{IC}\\0&1\end{bmatrix},\qquad p_I=R_{IC}\,p_C+t_{IC}$$

即 **`T_IC` 把相机系下的点变到 IMU 系下**（"相机 → IMU"）。

> ⚠️ **注意**：Kalibr 输出的 `T_cam_imu` 语义**相反**（IMU → 相机）。本程序在配置里用
> `extrinsic.convention: T_IC_means_camera_to_imu` 显式声明，并在结果文件里原样回写。

### 6.3 数据格式

```
data/session_01/
├── images/000000.png ...
├── image_timestamps.txt      # "<文件名> <主机单调时钟秒>"
├── imu.txt                   # "# timestamp gx gy gz ax ay az"（秒 / rad/s / m/s²）
├── imu_h7_full.csv           # 板载毫秒 + 六轴 + 欧拉角 + 四元数 + 主机时钟
└── imu_raw.bin               # 原始串口字节流（可事后重放复核）
```
